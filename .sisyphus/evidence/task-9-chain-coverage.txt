## T1 vs T7: Functional Difference

The critical functional difference between T1 and T7 is the source of `memory_context`:

- **T1 Legacy**: `memory_context` comes from `_format_eval_memory_block()` — a benchmark-local substitute that does NOT call production `build_memory_context()`
- **T7 Parity**: `memory_context` comes from `build_memory_context()` — the actual production function

This means:
- T1 benchmark could NOT measure changes to production `build_memory_context()`
- T7 parity path CAN measure production `build_memory_context()` changes

## No-Transform Invariant: Parity vs Legacy

Both T1 and T7 satisfy the no-transform invariant for their respective prompt chains:

- **T1 Legacy**: After `assemble_system_prompt()` returns at line 490, `system_prompt` is only assigned (line 490), passed to `answer_with_llm()` (line 654), and included in result dict (line 704)
- **T7 Parity**: After `assemble_system_prompt()` returns at line 131, `system_prompt` is only assigned (line 131), passed to `answer_with_llm()` (line 140), and included in result dict (line 164)

The difference is not in transform operations but in which formatter feeds the production assembly:
- T1 uses `_format_eval_memory_block()` (benchmark-local)
- T7 uses `build_memory_context()` (production)
